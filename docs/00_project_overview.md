# 00. Обзор проекта

## Постановка

Корпоративный русскоязычный RAG-чатбот Альфа-Банка. По тройке
`(query+dialog, retrieved_context, llm_answer)` нужно per-case предсказать:

- **faithfulness ∈ {0,1}** — ответ опирается ИСКЛЮЧИТЕЛЬНО на предоставленные
  чанки: не добавляет фактов вне контекста, не искажает числа/ставки/сроки,
  не смешивает информацию из разных чанков в неверное утверждение, не опускает
  важные детали, меняющие смысл;
- **relevance ∈ {0,1}** — ответ полностью соответствует вопросу клиента
  (с учётом истории диалога), покрывает все части вопроса, не подменяет ответ
  общими словами;
- **reliable = faithful AND relevant** — целевая метка.

Метрика: **f1-macro по reliable** (primary); f1-macro по faith и rel — диагностика.

## Ограничения

1. **Local models only** — внешние LLM API запрещены (защита клиентских данных).
2. Малый корпус: **5000 примеров**, открытый train + **приватный test**
   (трогается один раз в конце проекта, не нами — платформой).
3. Дисбаланс классов в сторону положительных меток.
4. У подмножества кейсов — **маркеры**: один или несколько из 13 типов ошибок
   (примеры: `hallucination`, `incomplete_answer`, `off_topic_answer`; полный
   словарь — от кураторов, хранить в `configs/markers.yaml`).

| # | Метод | Ветка |

## Гипотезы, которые закрывают наши ветки

- **H1** (совместно с веткой 1): fine-tuned judge превосходит prompt-optimized
  judge на reliable f1-macro. Наш вклад — правая часть сравнения: тот же
  backbone (Qwen2.5-7B-Instruct), та же схема извлечения вероятностей.
- **H4**: SelfCheckGPT-наследники дают полезный сигнал на faithfulness, но
  уступают supervised-методам на relevance.
- **H5**: маркеры как текстовый feedback — сильный сигнал при промпт-оптимизации
  (GEPA с маркер-фидбеком vs GEPA с голым «верно/неверно», равный бюджет и seed).

## Единый backbone

`Qwen/Qwen2.5-7B-Instruct` через vLLM (OpenAI-compatible endpoint). Менять
backbone без синхронизации со всей командой нельзя — сломается H1.
Reflection-LM для GEPA — более крупная локальная модель
(`Qwen/Qwen2.5-32B-Instruct`), используется только на этапе оптимизации.
