# Method 3/6 selective port

The `m3-m6` branch has a separate project layout and no common merge base with
the current `main`, so its code is being ported selectively instead of merged
directly.

## Integrated now

- `m3_zero_shot`, `m3_few_shot`, `m3_gepa`: Method 3 judge prompt modes with
  the axis-independence rule from `m3-m6`. They write the standard
  `Prediction` JSONL format and are available in `scripts/run_benchmark.py`.
- `m3_openai`: Method 3 zero-shot prompt through an OpenAI-compatible chat
  completions endpoint with local JSON file cache.
- `m6_selfcheck`: Method 6 prediction mapping from precomputed SelfCheck-style
  features to standard `Prediction` JSONL.
- `scripts/prepare_m6_samples.py`: local sample-cache generation for Method 6
  using either `--backend dummy` for smoke tests or `--backend mlx` for real
  local model sampling.
- `scripts/prepare_m6_features.py`: NLI/embedding feature extraction from that
  sample cache.
- Pure Method 6 feature functions: sentence splitting, SelfCheck contradiction
  aggregation, semantic clusters, and entropy.
- Tests for Method 3 prompt/parser, Method 6 feature logic, Method 6 prediction
  mapping, and unified benchmark command construction.

## Run through the unified interface

```bash
python scripts/run_benchmark.py \
  --data data/dummy.jsonl \
  --methods m3_zero_shot \
  --output-dir results/benchmark_m3
```

Few-shot mode uses `configs/few_shot.yaml` by default:

```bash
python scripts/run_benchmark.py \
  --data data/dummy.jsonl \
  --methods m3_few_shot \
  --m3-examples configs/few_shot.yaml \
  --output-dir results/benchmark_m3_few_shot
```

GEPA mode consumes a ready evolved prompt file:

```bash
python scripts/run_benchmark.py \
  --data data/dummy.jsonl \
  --methods m3_gepa \
  --m3-prompt-file artifacts/m3_optimized_prompt.txt \
  --output-dir results/benchmark_m3_gepa
```

OpenAI-compatible backend:

```bash
OPENAI_API_KEY=... python scripts/run_benchmark.py \
  --data data/dummy.jsonl \
  --methods m3_openai \
  --model Qwen/Qwen2.5-7B-Instruct \
  --m3-api-base http://localhost:8000/v1 \
  --m3-cache-dir results/m3/cache \
  --output-dir results/benchmark_m3_openai
```

For smoke tests without a real MLX model:

```bash
python scripts/run_benchmark.py \
  --data data/dummy.jsonl \
  --methods m3_zero_shot \
  --m3-backend dummy \
  --output-dir results/benchmark_m3_dummy
```

Method 6 requires precomputed features keyed by sample `id`:

```bash
python scripts/prepare_m6_samples.py \
  --data data/organizers.jsonl \
  --output-dir results/m6/samples \
  --backend mlx \
  --n-samples 5

python scripts/prepare_m6_features.py \
  --data data/organizers.jsonl \
  --samples-dir results/m6/samples \
  --output results/m6/features.jsonl

python scripts/run_benchmark.py \
  --data data/organizers.jsonl \
  --methods m6_selfcheck \
  --m6-features results/m6/features.jsonl \
  --output-dir results/benchmark_m6
```

## Not ported yet

- Cloud/OpenAI-compatible client, async client, data-leak guards, DVC, MLflow,
  and visualization dashboards from the old branch.
- GEPA prompt evolution workflow. The benchmark can consume an evolved prompt,
  but it does not optimize one yet.

These pieces should be added only after they are adapted to the current
`rag_reliability` schema, dataset loader, benchmark runner, and demo UI.
