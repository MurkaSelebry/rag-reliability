# Визуализации результатов (этапы −1 … −0.25, cloud)

Снапшот всех визуализаций веток «Метод 3» (LLM-as-judge + GEPA) и «Метод 6»
(SelfCheck + semantic entropy) с разбором того, что на них видно.
Справочник метрик — в **[METRICS.md](METRICS.md)**.

> ⚠️ **Статус чисел.** Всё построено на синтетическом псевдо-корпусе (SberQuAD → 300
> кейсов, сплит 240/30/30, метки искусственные). Числа отладочные: гипотез H1/H4/H5 они
> не доказывают и в отчёт проекта не идут (docs/07). Здесь важны **направления и
> механика**, не абсолютные значения. На реальном корпусе кураторов визуализации будут
> содержать тексты кейсов — тогда эта папка наследует статус данных (не выносить за
> периметр команды).

## Разбор результатов по визуализациям

### 1. Лидерборд f1_reliable (dashboard / report, секция 2–3)

| вариант | val | test | gap |
|---|---|---|---|
| few_shot | **0.824** | 0.691 | +0.132 |
| gepa_markers_s1 | 0.824 | 0.583 | **+0.240 ⚠** |
| zero_shot | 0.792 | 0.661 | +0.131 |
| gepa_plain_s1 | 0.760 | 0.697 | +0.063 |
| gepa_markers_s0 | 0.729 | 0.764 | −0.036 |
| gepa_plain_s0 | 0.722 | 0.661 | +0.062 |

**Что видно.** (1) Ручной few_shot — лучший на val и стабильный: 7 примеров с якорями
обеих осей дали +0.032 к zero_shot. (2) GEPA на light-бюджете **не превзошёл few_shot**
— поэтому по стоп-правилу medium-бюджет не запускался. (3) `gepa_markers_s1` — учебный
пример переобучения промпта: на val сравнялся с few_shot, на test просел до 0.583
(gap +0.240 при пороге тревоги 0.04). (4) Средний выигрыш markers−plain: val +0.035,
test −0.005 — **на синтетике эффект маркеров не удерживается**, что ожидаемо: здесь
маркеры детерминированы типом кейса и не несут информации сверх метки. Это репетиция
механики H5, не её проверка.

### 2. `figs/m3_box_p_faith.png` — боксплот p_faith по типам кейсов

**Что видно.** clean ≈ 1.0, hallucination ≈ 0.33, incomplete ≈ 0.66 — судья разводит
эти типы. Но **off_topic_answer ≈ 0.24 при истинной метке faith=1** — главный
негативный результат ветки: 7B-судья считает ответ «не на тот вопрос» ещё и
неверным по фактам, хотя факты взяты из контекста. Не лечится ни правилом в промпте
(правка B1: 0.000→0.005), ни few-shot-якорем (0.202→0.240 при цели >0.5). Вывод:
ограничение backbone-модели; проверяется на более крупной модели на local-этапе.

### 3. `figs/m3_box_p_rel.png` — боксплот p_rel по типам кейсов

**Что видно.** off_topic p_rel ≈ 0.33 против clean ≈ 0.85 — ось relevance работает:
сигнал clean−off_topic = +0.528 (порог приёмки +0.5). Важно в паре с фигурой 2: правило
независимости осей развело relevance (нет «размытия» из правки B1), но не починило
faith-путаницу. Оси ведут себя по-разному — именно поэтому они меряются раздельно.

### 4. `figs/m3_reliability_faith.png` — калибровочная диаграмма судьи

**Что видно.** Кривая идёт «ступенькой» выше диагонали в левой части: вероятности
из logprobs почти бимодальны (масса у 0 и у 1), в средних бинах мало кейсов.
Для бинаризации это не мешает (пороги подбираются на val), но использовать
p_faith как откалиброванную вероятность без калибровки (изотоника/Platt) нельзя.
Числа у точек — размер бина: выводы по средним бинам ненадёжны.

### 5. `figs/m3_f1_curve.png` — f1(t) по осям

**Что видно.** Из-за бимодальности p кривые f1(t) имеют широкие плато — метрика
малочувствительна к точному значению порога в широком диапазоне; подобранные на val
пороги (t_faith=0.03, t_rel=0.01) лежат на левом плато: выгоднее почти всех считать
PASS и ловить только уверенные FAIL. Резкий обрыв p_rel на высоких порогах — признак
того, что даже у clean-кейсов p_rel не всегда прижат к 1.0.

### 6. `figs/m6_scatter.png` — m6: contradiction × entropy

**Что видно.** Оранжевые точки (hallucination) уходят вправо по
`selfcheck_contra_mean` (Δ против clean = **+0.307**) — противоречие сэмплов ответу
ловит вброшенный факт. По вертикали (entropy) типы перемешаны — энтропия слабо
разделяет. Зелёные (incomplete) в левом нижнем углу: consistency-метод **слеп к
неполноте** (ответ короче, но ничему не противоречит) — это зона ответственности
judge-метода (H4). Размер точки = n_clusters.

### 7. Абляция энтропии (dashboard-heatmap; сырьё в `m6_entropy_ablation_val.json`)

| thr \ N | 3 | 5 | 10 |
|---|---|---|---|
| 0.30 | +0.229 | +0.065 | +0.441 |
| 0.40 | +0.416 | +0.017 | +0.343 |
| 0.50 | +0.335 | **−0.064** | +0.249 |

**Что видно.** Δ semantic_entropy (hallucination − clean) в основном положительна, но
**мала и немонотонна** по N и порогу — при thr=0.5 знак даже флипается (+0.335 → −0.064
→ +0.249). Чистая инверсия B4 с прошлого корпуса не воспроизвелась, но устойчивого
сигнала тоже нет: энтропия чувствительна к калибровке NLI-эквивалентности и к выборке.
**Решение:** faith-сигнал Метода 6 строится на contradiction; энтропию не наращивать
(B4 в силе). На реальном корпусе порог NLI подбирать на dev-val.

### 8. `gepa/*.md` — эволюция GEPA-промптов

**Что видно.** По каждому прогону — таблица кандидатов с val-score и тексты инструкций.
Рефлексия-72B делает осмысленные правки: сохраняет правило независимости осей (B1),
добавляет структурированные указания и few-shot-примеры из train. Лучшие кандидаты:
0.717 (seed 0) и 0.733 (seed 1) — **одинаковые для markers и plain**, ещё одно свидетельство,
что на синтетике маркер-фидбек ничего не добавляет. Бюджет: ~500–600 вызовов 7B +
20–25 вызовов 72B на прогон.

### 9. `figs/explorer_*.png` — Streamlit-эксплорер (4 страницы)

- **cases** — фильтры по split/kind/variant/extract_method/диапазонам p + чекбокс
  «только ошибочные при порогах из report»; карточка кейса показывает вердикты **всех**
  вариантов и raw-вывод судьи. На скриншоте виден типовой прокол: `pseudo_00218`
  (incomplete) — p_faith 0.996 при истинном faith=0 (неполнота не поймана), и
  `pseudo_00059` (off_topic) — p_faith 0.008 при faith=1 (та самая путаница осей).
- **disagreements** — кейсы, где reliable-вердикты пары вариантов разошлись,
  сортировка по |Δp|; ответ на вопрос «что изменил GEPA-промпт против few_shot».
- **m6** — N сэмплов кейса бок о бок с ответом: наглядно виден alignment-collapse
  (почти одинаковые сэмплы) и источник contradiction-сигнала.
- **gepa** — финальная инструкция + diff против SEED_INSTRUCTION.

## Сводка выводов этапов (что несём на local)

1. **off_topic faith-путаница — ограничение 7B-судьи** (не промпта): нужен крупнее
   backbone; правило осей и few-shot-якоря сохраняем.
2. **GEPA-механика работает** (обвязка, метрика ±маркеры, стоп-правила, контроль
   переобучения), но проверка H5 возможна только на реальных маркерах кураторов.
3. **m6: faith = contradiction**, энтропия — ненадёжный признак; incomplete ловится
   только judge-методом (разделение ролей методов по H4).
4. Вероятности судьи бимодальны — для калиброванных p нужна изотоника (в m6 уже так).

## Как перегенерировать

```bash
python -m tools.make_figs   --config configs/config.cloud.yaml --split val \
    --m3-pred predictions/cloud/m3/few_shot/val.jsonl --m6-features artifacts/cloud/m6_features/val.jsonl
python -m tools.make_report --root . --out artifacts/report/index.html
python -m tools.entropy_ablation --config configs/config.cloud.yaml --split val
python -m src.m3.gepa_report --variant markers --seed 0   # × variant/seed
```
(и скопировать свежие файлы сюда; dashboard.html — ручной снапшот этапа −0.25).
