# 14. Полное описание проекта: от постановки до результатов

Итоговый документ веток «Метод 3» (LLM-as-judge + GEPA) и «Метод 6»
(SelfCheckGPT + semantic entropy) проекта **Assessing the Reliability of
Responses in RAG Systems** (SMILES × Alfa Bank). Собирает всю историю:
постановку, данные, устройство методов, хронологию этапов и все численные
результаты, включая финальный прогон на полном датасете организаторов
(2026-07-12). Ссылки на детали — в конце каждого раздела.

---

## 1. Постановка задачи

Внутренний RAG-чатбот Альфа-Банка отвечает клиентам по базе знаний. По тройке
`(query + dialog, retrieved_context, llm_answer)` требуется per-case предсказать
две бинарные метки качества ответа:

- **faithfulness ∈ {0,1}** — ответ опирается *исключительно* на предоставленные
  чанки: не добавляет фактов из обучения модели, не искажает числа/ставки/сроки,
  не смешивает информацию из разных чанков, не опускает детали, меняющие смысл;
- **relevance ∈ {0,1}** — ответ полностью соответствует вопросу клиента с учётом
  истории диалога, покрывает все части вопроса, не подменяет ответ общими словами.

Целевая метка и метрика:

```
reliable = faith AND rel        # primary: f1-macro(reliable)
```

f1-macro по faith и rel — вспомогательная диагностика. Методы обязаны выдавать
**вероятности** (`p_faith`, `p_rel`), а не бинарные метки; бинаризация — только
порогами, подобранными на dev-val (контракт платформы, docs/02).

Гипотезы, которые питают ветки:

- **H1**: неоптимизированный LLM-судья против supervised-подходов — где планка?
- **H4**: alignment-collapse — согласованный генератор сэмплирует галлюцинации
  стабильно, что ломает consistency-методы;
- **H5**: даёт ли маркерная разметка ошибок (feedback с глоссарием маркеров)
  выигрыш в GEPA-оптимизации промпта против plain-feedback.

Жёсткие правила: local models only для данных проекта (облако — только по явному
opt-in владельца данных или на синтетике), сплиты неприкосновенны, dev-test не
участвует ни в каких решениях, всё дорогое кэшируется, каждый прогон пишет
`run.yaml` (конфиг + git-хэш + seed).

*Детали: docs/00, docs/02, CLAUDE.md.*

## 2. Данные

### 2.1 Корпус организаторов (реальные данные)

CSV от кураторов: диалог, ответ бота, до 8 чанков знаний, две бинарные метки и
текстовые маркеры причин ошибок (13 типов: `reason_hallucinated_fact`,
`reason_chunk_fact_mixup`, `reason_missed_chunk_conditions`, …).

- **2245 строк → 2233 кейса** после детерминированного отброса 12 точных дубликатов.
- Баланс: faith=1 — 73.5%, rel=1 — 87.7%, reliable — 72.3%.
- Маркеры размечены у 158 кейсов (7%); топ-5: hallucinated_fact 35,
  answer_for_operator 27, chunk_fact_mixup 27, irrelevant_chunk_used 25,
  off_topic_answer 19.
- Ячейка (faith=1, rel=0) редкая — 1.2% корпуса: путаница осей не главная
  проблема реального бота.
- Длины: ответ p50 = 59 слов; контекст p95 = 4.9k токенов — влезает в 8–16k.
- Ошибки бота тонкие (упущенные условия, смешение чанков), не грубые инъекции.

Сплиты — group-aware по нормализованным запросам (утечки между сплитами
исключены), seed 42: **train 1787 / val 223 / test 223**. Провизорные, до
канонических сплитов платформы; воспроизводятся `make splits` бит-в-бит.

### 2.2 Псевдо-корпус (синтетика для cloud-отладки)

300 кейсов из SberQuAD (seed 42), микс 2:1:1:1 — clean / hallucination /
incomplete_answer / off_topic_answer; сплиты 240/30/30. Генератор — тот же

## 3. Метод 3: LLM-as-judge + GEPA

### 3.1 Устройство

Один вызов судьи (Qwen2.5-7B-Instruct) на кейс; три ступени стоимости инструкции:

1. **zero_shot** — рукописная инструкция с определениями faith/rel на русском;
   формат вердикта `FAITHFULNESS: PASS|FAIL` + `RELEVANCE: PASS|FAIL`.
2. **few_shot** — та же инструкция + 7 реальных примеров с ручным разбором
   (clean ×2, hallucination, incomplete ×2, off_topic ×2, chunk_fact_mixup);
   пример ячейки (faith=1, rel=0) — якорь независимости осей.
3. **gepa** — автоматическая эволюция инструкции (DSPy GEPA) по feedback-метрике;
   варианты H5: `gepa_markers` (feedback + глоссарий маркеров) vs `gepa_plain`.
   Reflection-LM: 32B локально / 72B в облаке.

Ключевые решения:

- **Вероятности из logprobs**: `p_faith = softmax(logprob(PASS), logprob(FAIL))`
  на позиции первого вердикта, `p_rel` — на позиции второго. Fallback-цепочка:
  logprobs → regex (0.9/0.1) → 0.5/0.5; кейс не может быть потерян.
- DSPy используется **только для оптимизации**; инференс — собственный
  `JudgeClient` (доступ к logprobs). Схема выхода совпадает с Методом 1 ради
  честного H1.
- Правило независимости осей в инструкции (правка B1): faith оценивается только
  против [CTX].

### 3.2 Хронология и результаты

**Этап −1 (cloud, синтетика, 30 val):** пайплайн живой, 100% извлечение из
logprobs. zero_shot 0.792 → few_shot **0.824** (f1 reliable); сигнал faith
Δp(clean−halluc) укрепился +0.532 → +0.635. Правка B1 путаницу осей на 7B не
вылечила (off_topic p_faith 0.000 → 0.005).

**Этап −0.5 (cloud, GEPA на синтетике):** механика (эволюция промпта, H5-обвязка,
стоп-правила) отлажена. gepa_markers seed1 отбракован стоп-правилом (зазор
val−test +0.241). Средние markers vs plain: +0.035 val / −0.005 test — шум:
на синтетике маркеры детерминированы типом кейса, H5 честно мерить только на
реальном корпусе.

**Этап 1 (OpenRouter/Phala, реальный корпус, opt-in владельца данных):**

| вариант | модель | val | test | статус |
|---|---|---|---|---|
| surface-логрег (baseline) | — | **0.6133** | **0.5982** | планка |
| m3 zero_shot | 7B | 0.5678 | 0.5841 | стоп-сигнал |
| m3 few_shot | 7B | 0.5718 | 0.5309 | не помог |
| m3 zero_shot (абляция) | 72B | 0.5894 | — | размер не лечит |
| m3 few_shot (абляция) | 72B | 0.5235 | — | хуже 7B |
| m3 GEPA-light markers s0 | 7B | 0.5502 | — | checkpoint < few_shot → **стоп** |

Диагностика провала: извлечение исправно (100% logprobs); путаница осей не
главная (ячейка (1,0) редкая, p_faith на ней 0.751); главное — **слабое
разделение тонких ошибок**: Δp_faith(faith=1 − faith=0) = +0.088 на реальном
против +0.53 на синтетике; судья переуверен в PASS (средний p_faith на
unfaithful-ячейках 0.65–0.88); recall unreliable 0.26–0.29. По маркерам:
hallucinated_fact ловится частично (0.24–0.67), chunk_fact_mixup и
missed_chunk_conditions — практически нет. GEPA-эскалация остановлена
стоп-правилом; полные H5-прогоны (markers/plain × 3 seed) отложены до vLLM.

**Полный датасет организаторов (2026-07-12):** train-часть (1787 кейсов)
докуплена для zero_shot и few_shot; 100% logprobs на всех 2233 кейсах обоих
вариантов. Пороги — только с val:

| вариант | пороги t_faith/t_rel | val | test | train | **full (2233)** |
|---|---|---|---|---|---|
| zero_shot | 0.30 / 0.63 | 0.5678 | 0.5841 | 0.5478 | **0.5541** |
| few_shot | 0.98 / 0.63 | 0.5718 | 0.5309 | 0.5318 | **0.5359** |

Экстремальный порог t_faith=0.98 у few_shot — ещё один симптом переуверенности
судьи в PASS. Вывод этапа 1 подтверждён на полном корпусе.

## 4. Метод 6: SelfCheckGPT + semantic entropy

### 4.1 Устройство

Идея: если бот галлюцинирует, его пересэмплированные ответы противоречат друг
другу. Три независимых этапа, каждый со своим поэлементным кэшем:

1. **Сэмплирование** — промпт бота + [CTX] + [Q] → 10 сэмплов (T=0.8,
   top_p=0.95, один батч-запрос n=10).
2. **Фичи** — SelfCheck-NLI (mDeBERTa-v3-XNLI: P(contradiction) сэмпл ↔
   предложение ответа; длинные premise режутся окнами 128 токенов с перекрытием
   и max-агрегацией); semantic entropy (двунаправленный entailment → union-find
   → кластеры → H, `n_clusters`, `answer_in_top_cluster`); косинус q↔a
   (multilingual-e5-large).
3. **Прогноз** — `p_faith`: изотоническая регрессия на z(contra)+z(entropy),
   калибровка на val (unsupervised по разметке faith); `p_rel`: логрег на train
   (supervised-отступление, оговорено в limitations). Отчёт дополнительно
   считает `share_single_cluster` — маркер alignment-collapse (H4).

### 4.2 Результаты

**Синтетика (cloud):** contradiction — сильный faith-сигнал:
Δcontra(halluc − clean) = **+0.939** (N=5; 0.971 против 0.031). Релевантность
лучше всего ловится косинусом q↔a (f1_rel 0.627). Итог на 20 кейсах:
f1 reliable 0.596 (выборка крошечная, числа отладочные).
`share_single_cluster` = 0.20 — collapse уже виден.

**Semantic entropy — честный негативный результат (правка B4):** гипотеза «при
N=10 энтропия вырастет» опровергнута — Δentropy +0.009 (N=5) инвертируется в
−0.164 (N=10). Причина: чистые ответы расходятся на парафразы (много кластеров),
галлюцинации кучные и стабильные. Признак чувствителен к N и порогу
NLI-эквивалентности. Решение: энтропия остаётся иллюстрацией H4, faith строится
на contradiction; N=5 — дефолт.

**Реальный корпус — статус «до GPU»:** сэмплы val+test (446 × 10) закэшированы
(`artifacts/alfa_or/m6_samples/`); NLI-фичи считаются >8 мин/кейс на CPU
(~60 часов на val+test) — ждут GPU (~1 мин/кейс). Без train-фич нет
p_rel-логрега, поэтому предсказаний на реальном корпусе пока нет. Ограничение
честности: реальный промпт бота кураторами не выдан — сэмплирование идёт
прокси-промптом; при получении настоящего нужно пересэмплировать в новый кэш.

*Детали: docs/04, docs/08, docs/09.*

## 7. Что сработало / что нет

**Сработало:**
- Оба пайплайна механически исправны: 100% извлечение вероятностей из logprobs
  (2233 кейса × 2 варианта без единого фолбэка), кэши, детерминизм, guard от
  утечки данных.
- Contradiction-сигнал М6 на галлюцинациях: Δ +0.939.
- Стоп-правила экономят бюджет: переобученный GEPA-seed (зазор +0.241) и слабый
  checkpoint (0.550 < 0.572) отсеяны до дорогих прогонов.
- Инфраструктура results/: тесты (100 passed, ruff clean), сводные метрики,
  воспроизведение одной страницей.

**Не сработало:**
- LLM-судья на тонких ошибках реального бота: разделение сигнала упало в ~6 раз
  против синтетики (Δp_faith +0.53 → +0.088).
- Semantic entropy как faith-признак: шум на N=5, инверсия на N=10.
- Few-shot и рост backbone до 72B на реальном корпусе.
- Путаница осей off_topic→faith на 7B не чинится ни промптом, ни примерами.

## 8. Открытые вопросы и план

1. **vLLM-этап (local):** поднять Qwen2.5-7B и 32B; проверить, берёт ли 32B
   путаницу осей; честное H5 (markers vs plain × 3 seed) на реальном корпусе,
   где маркеры ортогональны метке. Финальные числа проекта — только local.
2. **Метод 6 на GPU:** фичи батчем, решить объём train-сэмплов (1787×10 или
   подвыборка 800), замерить alignment-collapse на реальном боте, абляции
   N ∈ {3,5} из того же кэша.
3. **Вопросы кураторам:** промпт реального бота (для честного сэмплирования М6),
   трактовка 18 кейсов «маркер при reliable=1», колонка `full_query`, 15 кейсов
   с пустым query, фиксированный private-test при росте корпуса до 5k.
4. **GEPA-эскалация** — стоп до vLLM (рекомендация владельцу; альтернативы —
   дешёвое H5-сравнение light 2×3 seeds или medium-бюджет).
